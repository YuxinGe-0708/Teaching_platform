## 2 系统结构设计及子系统划分

系统采用前后端分离架构，后端基于 Spring Boot，前端基于 Vue 3。整体划分为以下子系统：

1. **用户认证与权限子系统**：负责用户注册、登录、角色识别（学生/教师/管理员）、Token 管理及权限校验。
2. **课程管理子系统**：负责课程创建、修改、查询、归档，班级管理，教学资源上传与下载。
3. **作业与考试子系统**：负责作业/考试的发布、修改、删除，题型配置（客观题、主观题、编程题），截止时间管理。
4. **提交与评测子系统**：接收学生提交内容，对客观题自动判分，对编程题调用第三方 Judge API 进行评测，记录评测状态和结果。
5. **成绩统计子系统**：根据权重计算加权平均分，生成班级成绩分布直方图、及格率、平均分等统计信息。
6. **消息通知子系统**：站内通知的发送、已读/未读管理，支持课程通知、作业批改通知、系统公告等。
7. **AI辅助子系统**：对接大语言模型 API，提供知识点解释、笔记总结、思维导图生成等功能。
8. **管理员后台子系统**：用户管理、系统配置、日志查看、公告发布。

子系统间的调用关系：

- 所有子系统均依赖用户认证与权限子系统进行身份验证和权限控制。
- 作业与考试子系统调用提交与评测子系统进行判题。
- 成绩统计子系统读取作业/考试子系统和提交与评测子系统的数据。
- 消息通知子系统监听作业发布、提交批改等事件，向相关用户发送通知。
- AI辅助子系统可被课程学习页面和作业页面独立调用。

## 3 功能模块设计

### 1. 用户管理模块

- **模块编号**：M1
- **模块名称**：用户管理模块
- **输入**：用户注册信息（用户名、密码、真实姓名、邮箱、角色）、登录信息（用户名、密码）、个人信息修改请求、密码重置请求（管理员）
- **处理**：
    - **注册**：验证用户名唯一性，密码复杂度（长度≥6，包含数字和字母），对密码进行 BCrypt 加密后存入数据库。
    - **登录**：根据用户名查询用户，验证密码（BCrypt 匹配），生成 JWT Token，返回用户角色和跳转目标。
    - **个人信息修改**：验证修改权限（仅本人或管理员），更新邮箱、手机号、头像等字段。
    - **密码重置（管理员）**：管理员强制重置学生/教师密码，生成临时密码并加密存储。
- **算法描述**：
    - **注册算法**：`if (用户名已存在) 返回注册失败； else if (密码不符合规范) 返回密码格式错误； else 密码加密，写入 Users 表，返回成功。`
    - **登录算法**：`user = userDao.findByUsername(username); if (user == null) 返回用户不存在； else if (!bcrypt.matches(password, user.password)) 返回密码错误； else 生成 JWT Token，返回 Token 和角色。`
    - **个人信息修改算法**：`userDao.update(selective, userId); 返回更新结果。`
- **输出**：注册成功/失败信息、登录成功（含 Token 和角色）/失败信息、个人信息修改成功/失败信息。

### 2. 课程管理模块

- **模块编号**：M2
- **模块名称**：课程管理模块
- **输入**：课程信息（课程名称、课程编号、课程简介、封面、学分、学时）、教师ID、班级信息（班级名称、人数上限、邀请码）、教学资源（文件、标题、类型）
- **处理**：
    - **创建课程**：教师填写课程基本信息，系统生成课程ID，状态设为“草稿”。
    - **修改课程**：教师可修改课程简介、封面、学分、状态（进行中/结课）。
    - **查询课程**：学生端查询已选课程，教师端查询已创建课程，支持按名称、状态筛选。
    - **删除课程**：逻辑删除，将状态设为“归档”，已有选课记录的课程不可物理删除。
    - **班级管理**：在课程下创建班级，生成唯一邀请码；学生通过邀请码加入班级。
    - **上传资源**：教师上传 PPT、PDF、视频等，记录文件 URL 和所属章节。
- **算法描述**：
    - **创建课程算法**：`course.setCourseId(generateId()); course.setStatus("草稿"); courseDao.insert(course);`
    - **选课算法**：`if (课程状态 != "进行中") 返回不可选课； if (已选该课程) 返回重复选课； else 插入选课记录，更新班级当前人数。`
- **输出**：课程创建/修改/删除结果、课程列表、资源上传结果、班级加入结果。

### 3. 作业/考试模块

- **模块编号**：M3

- **模块名称**：作业 / 考试模块

- **输入**：任务信息（标题、说明、任务类型、开始时间、截止时间、满分、权重）、题目配置（JSON 格式，含题目文本、选项、标准答案、测试用例等）、发布班级范围

- **处理**：
	- **发布作业**：教师选定课程下班级，填写作业基础信息，配置题型（客观题设标准答案、编程题设测试用例与语言限制），提交后系统生成任务记录。
	- **修改作业**：作业未截止时，支持修改题目说明、截止时间、分值权重；作业截止后，禁止修改核心内容，仅可查看。
	- **查询作业列表**：学生端按所属课程筛选待提交 / 已提交作业；教师端按课程查看已发布作业，支持按状态、发布时间筛选。
	- **删除作业**：教师可删除未开始或已归档的作业，删除后保留历史记录，避免数据丢失。

- **算法描述**：
	- **发布作业算法**：`校验开始时间早于截止时间；序列化题目配置为JSON存入数据库；生成唯一任务ID并插入任务表；触发消息通知，推送至对应班级学生。`

- **输出**：作业发布 / 修改 / 删除结果、作业列表、作业详情信息

### 4. 提交与评测模块

- **模块编号**：M4
- **模块名称**：提交与评测模块
- **输入**：任务ID、学生ID、提交内容（客观题为选项/填空文本，编程题为代码文本及语言）、附件文件（主观题）
- **处理**：
    - **客观题提交**：系统根据标准答案即时判分，将得分和批改状态写入提交记录。
    - **编程题提交**：将代码、测试用例、语言、时间/内存限制封装为 JSON，异步调用第三方 Judge API（如 Judge0）。系统先创建提交记录（状态为“评测中”），然后发送 HTTP 请求至 Judge API，收到响应后解析结果（AC/WA/CE/RE/TLE），根据测试用例通过情况计算得分，更新提交记录状态和得分。
    - **主观题提交**：仅保存提交内容和附件，状态设为“待批改”，等待教师人工批改。
    - **评测重试**：若调用 Judge API 超时或返回5xx错误，自动重试最多2次（间隔2秒），仍失败则标记状态为“评测失败”。
- **算法描述**：
    - **客观题判分算法**：
        - 单选题/判断题：`submission.answer == standardAnswer ? fullScore : 0`
        - 多选题：`完全匹配得满分；子集匹配扣部分分；不匹配得0分`
        - 填空题（精确匹配）：`内容精准匹配得满分，否则得0分`
    - **编程题得分算法**：
        - 总分 `fullScore`，共有 n 个测试用例，权重分别为 `w1...wn`，总权重 `totalWeight = Σwi`。
        - 对于每个通过的测试用例（状态为 AC），得分 `score_i = fullScore * (wi / totalWeight)`。
        - 最终得分 `finalScore = Σscore_i`（通过用例）。
        - 整体状态：若所有用例通过则为 AC，部分通过为 PARTIAL，编译错误为 CE，运行错误为 RE，超时为 TLE。
- **输出**：提交记录、即时判分结果（客观题）、评测状态（编程题，可轮询获取）、最终得分。

### 5. 成绩统计模块

- **模块编号**：M5
- **模块名称**：成绩统计模块
- **输入**：课程ID、班级ID、学生ID、作业/考试列表及其权重
- **处理**：
    - **计算加权平均分**：遍历课程下所有已批改的作业/考试，根据每个任务的权重和学生的得分，计算加权平均分。
    - **生成成绩看板**：统计全班成绩分布（分数段人数）、平均分、最高分、最低分、及格率。
    - **导出成绩单**：提供 CSV/Excel 导出功能。
- **算法描述**：
    - **加权平均分算法**：`finalScore = Σ(score_i * weight_i) / Σ(weight_i)`，其中权重为教师设定的百分比（如作业占30%，考试占70%）。
    - **分数段统计算法**：遍历班级所有学生的最终成绩，按 [0,60)、[60,70)、[70,80)、[80,90)、[90,100] 区间计数，计算占比。
- **输出**：学生个人成绩单、班级成绩统计看板（含直方图数据）、导出文件。

### 6. 消息通知模块

- **模块编号**：M6
- **模块名称**：消息通知模块
- **输入**：触发事件（作业发布、作业批改完成、成绩公布、课程通知发布、系统公告）、目标用户/班级/角色
- **处理**：
    - **发送通知**：根据事件类型和接收范围，创建通知记录（标题、内容、类型、目标ID、接收范围）。支持发送给全体、指定角色、指定课程/班级、指定个人。
    - **查询通知**：用户登录后查询自己的未读/已读通知列表。
    - **标记已读**：用户阅读通知后，将通知ID加入该用户的已读列表（或更新 read_user_ids 字段）。
- **算法描述**：
    - **发送通知算法**：`notification = new Notification(title, content, type, targetType, targetId); notification.setCreateTime(now); notificationDao.insert(notification);`（不立即推送，由前端轮询或 WebSocket 实时获取）。
- **输出**：通知发送结果、用户通知列表、已读标记结果。

### 7. AI辅助模块

- **模块编号**：M7
- **模块名称**：AI辅助模块
- **输入**：用户提问文本、上下文信息（课程ID、当前课件章节、作业题目等）、输出格式要求（知识点解释/笔记总结/思维导图）
- **处理**：
    - **知识点答疑**：将用户问题与课程上下文拼接成 Prompt，调用大语言模型 API，返回自然语言解释。
    - **笔记总结**：用户上传自己的笔记文本或选择课件内容，调用大模型生成结构化总结。
    - **思维导图生成**：请求大模型返回 Markdown 格式的层级列表，前端解析为思维导图（如使用 ECharts 或 markmap）。
    - **会话记录**：保存每次问答的输入、输出、调用时间，用于后续分析和限流。
- **算法描述**：
    - **Prompt 构造算法**：`systemPrompt = "你是一位专业的教育助手，请用中文回答。"; userPrompt = "课程：" + courseName + "，问题：" + question;` 调用 API 时设置 temperature=0.7，max_tokens=1000。
    - **降级处理**：若 API 调用超时或返回错误，返回预设提示“AI助手暂时不可用，请稍后再试”。
- **输出**：AI 回答文本、笔记总结、思维导图结构数据（JSON或Markdown）。

### 8. 管理员后台模块

- **模块编号**：M8
- **模块名称**：管理员后台模块
- **输入**：用户账号信息（批量导入 Excel）、系统配置项（允许注册、首页布局等）、公告内容、日志查询条件
- **处理**：
    - **用户管理**：增删改查用户账号，重置密码，启用/禁用账号，分配角色。
    - **系统配置**：读取和修改系统参数（存储在系统配置表）。
    - **公告管理**：发布、编辑、置顶、删除平台级公告。
    - **日志查看**：查询操作日志、登录日志、异常日志，支持按时间、用户、操作类型筛选。
- **算法描述**：
    - **批量导入算法**：解析 Excel 文件，逐行校验数据（用户名唯一性、邮箱格式），对密码进行加密，批量插入数据库（使用 JDBC batch）。
- **输出**：用户操作结果、配置更新结果、公告发布结果、日志列表。

**功能接口**：

- 在线查看学生提交的代码或文档。
- 对主观题输入分数和评语。
- 对编程题可手动覆盖自动评测得分。
- 批量导出提交记录。

**数据接口**：
- 提交记录数据库：查询提交内容。
- 作业数据库：作业配置。

#### 成绩统计页面（教师）

**功能接口**：
- 查看班级成绩分布直方图。
- 查看每位学生的加权平均分及明细。
- 导出成绩单（Excel）。

**数据接口**：
- 提交记录数据库：获取每次作业得分。
- 成绩统计模块：计算加权平均分。

### 4.2 内部界面设计

#### 用户管理模块

**调用关系**：
- 课程管理模块：需要验证用户身份和角色（仅教师可创建课程）。
- 作业模块：需要验证用户是否为授课教师或选课学生。
- 管理员后台模块：管理员调用用户管理接口进行账号操作。

**数据接口**：
- 用户信息数据库：存储用户账号、密码（加密）、角色、状态。

#### 课程管理模块

**调用关系**：
- 用户管理模块：验证教师身份。
- 作业模块：课程下关联作业。
- 成绩统计模块：根据课程统计成绩。

**数据接口**：
- 课程数据库：课程信息、班级信息。
- 资源数据库：教学资源元数据。

#### 作业与考试模块

**调用关系**：
- 课程管理模块：获取课程和班级信息。
- 提交与评测模块：调用判题功能。
- 消息通知模块：作业发布时触发通知。

**数据接口**：

## 5 异常处理设计

### 5.1 出错信息管理

在系统运行过程中，可能会出现各种错误和异常情况，需要及时捕获并向用户提供清晰的错误信息。

**可能出现的错误和异常情况**：
1. 用户输入信息格式错误（如用户名长度不足、邮箱格式错误、日期格式错误等）。
2. 数据库连接失败或查询超时。
3. 第三方 Judge API 调用失败（超时、返回错误、配额不足）。
4. 大语言模型 API 调用失败或返回格式异常。
5. 文件上传大小超限或类型不支持。
6. 权限不足（越权访问）。
7. Token 过期或无效。

**处理方法与策略**：
1. 前端进行输入格式校验，后端再次校验，返回统一的错误码和提示信息（如“用户名至少4个字符”）。
2. 对数据库操作设置连接池和超时时间，捕获 SQLException 后返回“系统繁忙，请稍后重试”。
3. 对第三方 API 调用设置超时（30秒）和重试机制（最多2次），重试失败后返回“评测服务暂时不可用”。
4. AI 调用失败时返回预设降级文案“AI助手暂时无法回答，请稍后再试”。
5. 文件上传限制为最大10MB，仅允许常见类型（pdf, pptx, jpg, png, zip），超出返回错误提示。
6. 全局权限拦截器返回 403 状态码，前端跳转到无权限页面或弹窗提示。
7. Token 过期时前端自动跳转到登录页。

### 5.2 故障预防与补救

为了保障系统的稳定运行，需要预防各种可能导致系统故障的因素，并提供相应的补救措施。

**可能导致系统故障的因素**：
1. 数据库存储空间不足或连接数耗尽。
2. 第三方 API 服务宕机或限流。
3. 服务器 CPU/内存负载过高。
4. 代码逻辑错误导致空指针异常或死循环。

**预防措施**：
1. 定期监控数据库磁盘使用率，设置告警阈值；使用连接池（HikariCP）管理连接。
2. 对第三方 API 使用备用密钥或备用服务商（如 Judge0 免费版 + 备用自建评测机降级方案）。
3. 部署负载均衡和限流（使用 Redis 令牌桶限制 API 调用频率）。
4. 编写单元测试和集成测试，覆盖核心业务逻辑；使用 SonarLint 进行静态代码检查。

**补救措施**：
1. 数据库空间不足时，自动清理过期日志表（如操作日志保留30天）。
2. 第三方 API 不可用时，将评测任务放入本地队列，人工介入后重试或提供手动批改入口。
3. 服务器负载过高时，启用限流，返回“当前访问人数过多，请稍后重试”。
4. 系统崩溃后自动重启（使用 systemd 或 Docker 重启策略），并发送告警邮件给管理员。

### 5.3 系统维护设计

为了确保系统能够长时间稳定运行，需要定期进行系统维护和更新。

**系统维护计划**：
1. 每周日凌晨进行数据库全量备份（mysqldump），保留最近4周的备份。
2. 每月清理 Redis 过期键和无效会话。
3. 每季度进行性能评估，优化慢查询（使用 explain 分析）。
4. 定期更新服务器安全补丁和依赖库版本。

**问题处理策略**：
1. 用户通过反馈页面提交问题，系统自动记录到问题跟踪表。
2. 严重级别分为 P0（阻断）、P1（严重）、P2（一般）、P3（建议）。P0 问题需在2小时内修复并发布热补丁。
3. 发布更新前在测试环境验证，使用蓝绿部署或灰度发布降低影响。

## 6 性能优化和安全设计

### 数据存储安全性考虑

- **数据加密**：用户密码使用 BCrypt（强度10）加密存储。第三方 API 密钥（Judge API Key、大模型 API Key）使用 AES-256 加密后存入数据库，或使用环境变量注入。
- **访问控制**：数据库账号遵循最小权限原则，应用使用专用账号，仅授予 CRUD 权限。敏感表（如用户表）禁止批量导出。

### 数据传输安全性考虑

- **加密传输**：生产环境强制使用 HTTPS，配置 TLS 1.2+。开发环境可使用 HTTP 但需明确标识。
- **数据完整性验证**：对关键请求参数（如用户ID、订单ID）使用签名或防篡改校验（可选）。

### 数据访问安全性考虑

- **身份验证**：所有需要登录的接口必须携带 JWT Token（位于 Authorization 头），Token 有效期24小时，可刷新。
- **访问权限控制**：使用 Spring Security 基于角色的访问控制（RBAC）。例如：`@PreAuthorize("hasRole('TEACHER')")` 限制教师接口。数据级权限：教师只能操作自己的课程（通过课程ID与教师ID比对）。
- **审计日志**：记录所有用户登录、关键操作（创建课程、删除作业、批改分数）的日志，包括操作人、时间、IP、操作内容。

### 性能优化考虑

- **数据库索引优化**：对以下字段建立索引：User表的 username、role；Course表的 teacher_id、status；Task表的 course_id、end_time；Submission表的 task_id、student_id；Score表的 student_id、course_id。
- **数据缓存**：使用 Redis 缓存课程详情（缓存1小时）、作业列表（缓存10分钟）、用户权限信息。在提交作业或修改课程时主动清除相关缓存。
- **负载均衡**：单台服务器部署时使用 Nginx 作为反向代理，处理静态资源。如需扩展，可部署多实例并使用 Nginx 轮询。
- **异步处理**：编程题评测采用异步方式：提交后立即返回“评测中”，后台通过线程池或消息队列（如 Redis 队列）调用 Judge API，完成后更新数据库。前端轮询结果接口。
- **SQL 优化**：避免 N+1 查询，使用 MyBatis 的关联查询或批量查询。分页使用 `LIMIT offset, size`，对于大偏移量使用子查询优化。
